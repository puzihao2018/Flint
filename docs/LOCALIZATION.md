# 本地化维护

Flint 0.1.10 提供 `system` / `zh-CN` / `en`。设置在「设置与存储 → 语言」，默认跟随系统。中文系统语言（含 zh-Hant）显示简体中文，其他未支持的语言回退到 English。

## 结构

- `src/locales/zh-CN.json`、`en.json`：同一组消息键。采用中文源文案作为稳定键（类似 gettext），翻译值可独立调整。React 和 Rust 原生菜单共用文件。
- `src/i18n.ts`：纯函数，语言解析、消息查找及插值；无运行时翻译服务或网络请求。
- `src-tauri/src/preferences.rs`：在 Flint 数据目录下保存 `preferences.json`，先写临时文件再替换；写入失败不更新内存。偏好独立于服务配置。
- 主窗口和菜单栏通过 `preferences-changed` 事件同步。应用启动时由 WebView 提供系统语言，显式选择中文/英文时不受系统语言改变影响。
- `src/locales/backend-templates.json`：兼容现有引擎字符串的诊断模板，只作用于状态/错误展示，不修改日志。未知错误保留原文，不隐藏诊断信息。未来新增复杂诊断宜逐步改用错误码和参数，避免依赖字符串匹配。

## 修改文案

UI 中使用 `t("消息键")` 或 `t("删除 {name}", {name})`。完整句子整体翻译，不拼接多个语言片段。添加两份资源时保证键和 `{placeholder}` 集合一致。

`${port}` 等命令示例是文字，不是执行表达式；只传入明确的插值参数。服务名称、路径、版本、命令和日志由用户/服务提供，不进行翻译。无日志时的占位提示是 Flint UI 文案，可翻译。系统文件选择器和系统菜单的语言由操作系统管理。

新增引擎消息需为静态消息添加翻译，动态消息在 backend-templates.json 添加完整模板；保留端口、PID、文件路径等诊断值。不要对日志全文或用户内容执行匹配替换。

## 新增语言

1. 添加与现有键一致的语言 JSON。
2. 扩展 `Locale` / `LanguagePreference`、资源表、系统语言匹配和设置选项。
3. 扩展 Rust `Language`、`resolve_locale` 和原生菜单资源选择。引擎本身无需重复翻译业务逻辑。
4. 增加对应回退/保存/原生菜单测试，在实际窗口检查长文案和可访问名称。

`npm run test:i18n` 检查消息键与占位符一致、UI 静态键覆盖、市场文案、回退、特殊字符插值和嵌套诊断。`npm test` 同时执行 Rust 的语言偏好持久化/写入失败及服务回归测试。自动测试不替代 macOS 原生界面检查。
