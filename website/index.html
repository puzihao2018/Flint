launcher.yaml 
schemaVersion: "0.2"
id: example.python-webapp
version: "1.0.0"
name: Python Web App
environment:
  mode: existing
parameters:
  port:
    default: 3000
install:
  - program: uv
    args: [sync, --frozen, --no-dev]
service:
  protocol: http-api
  run:
    program: uv
    args:
      - run
      - --frozen
      - --no-sync
      - python
      - server.py
      - --host
      - "${host}"
      - --port
      - "${port}"
  healthPath: /healthz
For the Python/uv example project. Uses its existing directory.

Full installation guide↗

Early alpha. Builds are ad-hoc signed, not Apple-notarized. The first MinerU installation downloads dependencies and models.

Windows, Linux, Intel Mac, and automatic port discovery are planned, not available yet.

A few useful details.

Is MinerU an MCP server?

No. The built-in MinerU recipe exposes an HTTP API. Flint also supports custom MCP servers over Streamable HTTP. MCP stdio and legacy SSE are not supported yet.

Do my projects need a special launcher?

No. You can add a foreground command and an existing project folder directly. A launcher.yaml makes installation steps, arguments, and health checks easier to share. Your program must actually support the configured port.

What happens when I remove a service?

You choose whether to remove only its registration or also its managed environment, models, and service data. Flint preserves external project folders and shared caches. Selected managed files are deleted directly, without going to Trash.

Can I contribute a new integration?

Yes. Start with an issue describing the service and platform. Include its official source, pinned version, install and run commands, and a real health check. Recipes need actual installation and lifecycle testing before being listed as supported.
